Randomization — rand, randc, randomize()
rand · randc · constraint_mode · rand_mode · inline override
RAND
Definition
Randomization generates automatic stimulus values. rand picks freely (may repeat); randc cycles through all values once before repeating. Call randomize() to trigger generation — returns 1 on success.
Keyword / MethodMeaning
randRandom — value chosen randomly each call; may repeat
randcRandom-Cyclic — all values used before any repeat
randomize()Triggers randomization; returns 1=success, 0=fail
constraint_mode(0/1)Disable/enable a named constraint at runtime
rand_mode(0/1)Make a specific variable non-random / re-enable
randomize() with {}Inline constraint — single call override
soft constraintOverridable constraint — lower priority than hard
// ========================================================
// Topic 1: Randomization — rand, randc, randomize()
// File: 01_Randomization/randomization_demo.sv
// ========================================================

class Transaction;
  rand  bit [7:0] addr;   // random — may repeat
  randc bit [3:0] data;   // random-cyclic — all before repeat
  rand  bit       write;

  // ⭐ Constraint: word-aligned addr during write
  constraint align_c {
    if (write) addr[1:0] == 2'b00;
  }

  constraint addr_c {
    addr inside {[8'h00 : 8'hFF]};
  }

  // Soft: prefer data < 8 (can be overridden)
  soft constraint data_soft_c { data < 8; }

  function void display(string tag = "");
    $display("[%s] addr=0x%02h data=0x%01h write=%0b",
             tag, addr, data, write);
  endfunction
endclass

module randomization_demo;
  initial begin
    Transaction t = new();

    $display("=== Normal Randomization ===");
    repeat(5) begin
      if (!t.randomize())
        $fatal(1, "Randomization FAILED!");
      t.display("RND");
    end

    $display("\n=== Inline Override: force addr=0xAC ===");
    if (!t.randomize() with { addr == 8'hAC; write == 1; })
      $fatal(1, "Inline randomize failed!");
    t.display("OVR");

    $display("\n=== Disable align_c ===");
    t.align_c.constraint_mode(0);
    repeat(3) begin
      void'(t.randomize());
      t.display("NO_ALIGN");
    end
    t.align_c.constraint_mode(1); // re-enable

    $display("\n=== Fix addr (rand_mode off) ===");
    t.addr.rand_mode(0);
    t.addr = 8'hBB;
    repeat(3) begin
      void'(t.randomize());
      t.display("FIXED_ADDR");
    end
  end
endmodule

Constraints — inside, dist, implication, solve-before, foreach
inside · dist · if-then · -> implication · solve-before · soft · foreach
CONSTRAINT
Definition
Constraint blocks restrict the values that rand variables can take during randomize(). Multiple constraint types allow precise control over value distributions, ordering, and conditional rules.
Constraint TypeSyntaxMeaning
Rangex inside {[a:b]}x must be between a and b
Set membershipx inside {1,2,4,8}x must be one of listed values
Distribution :=x dist {0:=30, 1:=70}Absolute weight (30 hits vs 70 hits)
Distribution :/x dist {0:/30, 1:/70}Proportional (30% vs 70%)
Implication (if)if (mode==1) addr < 10Conditional constraint
Implication (→)(wr==1) -> (addr[1:0]==0)Equivalence implication
Solve-beforesolve a before bRandomize a first, use result for b
Foreachforeach(arr[i]) arr[i]<8Constrain each array element
Softsoft constraint c { x < 10; }Lower priority; can be overridden
// ========================================================
// Topic 2: Constraints
// File: 02_Constraints/constraints_demo.sv
// ========================================================

class Packet;
  rand bit [7:0]  addr;
  rand bit [7:0]  data;
  rand bit [1:0]  mode;       // 0=IDLE 1=READ 2=WRITE 3=BURST
  rand bit [3:0]  burst_len;
  rand bit [7:0]  payload[4]; // array

  // ⭐ inside: range constraint
  constraint addr_range_c {
    addr inside {[8'h10 : 8'hEF]};
  }

  // ⭐ dist: weighted distribution
  constraint data_dist_c {
    data dist { 8'h00          := 10,
                [8'h01:8'h7F] := 60,
                [8'h80:8'hFF] := 30 };
  }

  // ⭐ if-implication: BURST needs non-zero length
  constraint burst_c {
    if (mode == 2'b11) burst_len inside {[2:15]};
    else               burst_len == 0;
  }

  // ⭐ -> implication: WRITE must be word-aligned
  constraint write_align_c {
    (mode == 2'b10) -> (addr[1:0] == 2'b00);
  }

  // ⭐ solve-before: solve mode first, then burst_len
  constraint order_c {
    solve mode before burst_len;
  }

  // ⭐ foreach: constrain each array element
  constraint payload_c {
    foreach (payload[i]) payload[i] inside {[8'h01 : 8'hFE]};
  }

  // ⭐ soft constraint (overridable)
  soft constraint prefer_read_c { mode == 2'b01; }
endclass

module constraints_demo;
  initial begin
    Packet p = new();

    // Default constraints
    repeat(3) begin
      assert(p.randomize()) else $fatal(1,"Failed");
      $display("mode=%0d addr=0x%02h data=0x%02h burst=%0d",
               p.mode, p.addr, p.data, p.burst_len);
    end

    // Override soft: force BURST mode
    $display("\n=== Force BURST ===");
    p.randomize() with { mode == 2'b11; };
    $display("mode=%0d burst_len=%0d", p.mode, p.burst_len);

    // Disable data_dist_c at runtime
    p.data_dist_c.constraint_mode(0);
    p.randomize();
    $display("\n=== No dist: data=0x%02h", p.data);
  end
endmodule

  1. Write a constraint using inside and dist.
  2. Explain solve...before — when is it needed?

⚠️ Common Mistake: Confusing := (absolute weight) with :/ (proportional). With :=, weights are literal hit counts. With :/, they are percentage-proportional.

Must Memorize

  • inside {[a:b]} = range | inside {v1, v2} = set membership
  • dist {val := w} = absolute weight | dist {val :/ w} = proportional
  • if (cond) constraint = conditional (implication)
  • (a==1) -> (b==0) = equivalence implication operator
  • solve a before b = randomize a first so b can depend on its result

Inheritance & Polymorphism
extends · virtual · super · dynamic dispatch · $cast · polymorphic array
OOP
Definition
Inheritance lets a child class reuse parent members via extends. Polymorphism lets a parent handle call the correct child method at runtime using virtual functions — called dynamic dispatch.
ConceptKeywordEffect
InheritextendsChild gets all parent variables and methods
OverrideSame method name in childChild's version replaces parent's
Virtual methodvirtual function in parentEnables dynamic dispatch
Call parentsuper.method()Invoke parent version from child
Dynamic dispatchParent handle → child objectRuntime selects correct method
Downcast$cast(child, parent)Safe conversion back to child type
// ========================================================
// Topic 3: Inheritance & Polymorphism
// File: 03_Inheritance_Polymorphism/inheritance_demo.sv
// ========================================================

class BaseTransaction;
  rand bit [7:0] addr;
  rand bit [7:0] data;

  // ⭐ virtual — required for dynamic dispatch
  virtual function void display();
    $display("[BASE   ] addr=0x%02h  data=0x%02h", addr, data);
  endfunction

  virtual function string get_type();
    return "BASE";
  endfunction
endclass

class WriteTransaction extends BaseTransaction; // ⭐ extends
  rand bit parity;

  function void display(); // Override
    super.display();        // ⭐ call parent version
    $display("[WRITE  ] parity=%0b", parity);
  endfunction

  function string get_type(); return "WRITE"; endfunction
endclass

class ReadTransaction extends BaseTransaction;
  bit [7:0] rdata;

  function void display();
    super.display();
    $display("[READ   ] rdata=0x%02h", rdata);
  endfunction

  function string get_type(); return "READ"; endfunction
endclass

module inheritance_demo;
  initial begin
    BaseTransaction  base_h;  // ⭐ parent handle
    WriteTransaction wt = new();
    ReadTransaction  rt = new();
    wt.addr=8'hAB; wt.data=8'h12; wt.parity=1;
    rt.addr=8'hCD; rt.rdata=8'h77;

    // ⭐ Dynamic Dispatch
    base_h = wt;
    base_h.display();        // Calls WriteTransaction::display()
    base_h = rt;
    base_h.display();        // Calls ReadTransaction::display()

    // ⭐ Polymorphic array
    BaseTransaction txn_list[2];
    txn_list[0] = wt;
    txn_list[1] = rt;
    foreach(txn_list[i]) txn_list[i].display();

    // ⭐ $cast — downcast
    WriteTransaction wt2;
    base_h = wt;
    if ($cast(wt2, base_h))
      $display("Downcast OK: parity=%0b", wt2.parity);
    else
      $display("Downcast FAILED");
  end
endmodule

Expected Exam Questions

  1. Differentiate static and dynamic dispatch with code example.
  2. What is a virtual function? Why is it needed?
  3. Explain extends and super with example.

⚠️ Common Mistake: Forgetting virtual on the parent method. Without it, the parent handle always calls the parent's method — even when the object is a child type. No dynamic dispatch without virtual.

Must Memorize

  • extends = inherit all parent members and methods
  • virtual function in parent = enables dynamic dispatch (polymorphism)
  • Parent handle can hold child object — BaseTransaction t = new WriteTransaction()
  • Without virtual: parent method called (static). With virtual: child method called (dynamic)
  • $cast(child_h, parent_h) returns 1 if type matches, 0 if mismatch
  • super.method() explicitly calls parent's version from inside child

SystemVerilog Testbench Architecture
Generator · Mailbox · Driver · Interface · Monitor · Scoreboard · RefModel
TESTBENCH
Definition
A structured, layered testbench uses OOP components to generate stimulus, drive the DUT, monitor outputs, and verify correctness. Components communicate via mailboxes (thread-safe FIFOs).
ComponentRoleKey Point
TransactionData object carrying stimulus/responseContains rand fields + constraints
GeneratorCreates random transactionsCalls randomize(), puts in mailbox
MailboxThread-safe FIFO queueput() / get() pass data between components
DriverConverts transactions to pin-level signalsGets from mailbox, drives DUT via interface
InterfaceBundles signals between TB and DUTClocking block synchronizes to clock
MonitorPassively observes DUT outputNEVER drives signals — read-only
ScoreboardCompares actual vs expected outputReports PASS/FAIL
Ref ModelSoftware golden modelPredicts expected DUT output
// ========================================================
// Topic 4: Testbench Architecture
// Flow: Generator → [mailbox] → Driver → DUT
//       DUT → Monitor → [mailbox] → Scoreboard ↔ RefModel
// File: 04_Testbench_Architecture/testbench_architecture.sv
// ========================================================

class Transaction;            // ⭐ Data object
  rand bit [7:0] addr, data;
  rand bit       write;
  constraint c { addr inside {[0:255]}; }
endclass

class RefModel;              // ⭐ Golden model
  bit [7:0] mem[256];
  function bit [7:0] predict(Transaction t);
    if (t.write) mem[t.addr] = t.data;
    return mem[t.addr];
  endfunction
endclass

class Generator;             // ⭐ Stimulus generator
  mailbox #(Transaction) gen2drv;
  task run();
    Transaction t;
    repeat(10) begin
      t = new();
      assert(t.randomize());
      gen2drv.put(t);          // ⭐ Put into mailbox
    end
  endtask
endclass

class Scoreboard;            // ⭐ Checker
  mailbox #(Transaction) mon2scb;
  RefModel rm = new();
  int pass_cnt, fail_cnt;

  task run();
    Transaction t; bit[7:0] expected;
    forever begin
      mon2scb.get(t);          // ⭐ Get from mailbox
      expected = rm.predict(t);
      if (t.data === expected) pass_cnt++;
      else                     fail_cnt++;
      $display("[SCB] %s addr=%02h actual=%02h exp=%02h",
        (t.data===expected)?"PASS":"FAIL",t.addr,t.data,expected);
    end
  endtask
endclass

module testbench_architecture;
  mailbox #(Transaction) gen2drv = new();
  mailbox #(Transaction) mon2scb = new();
  Generator  gen = new();
  Scoreboard scb = new();

  initial begin
    gen.gen2drv = gen2drv;
    scb.mon2scb = mon2scb;
    fork
      gen.run();  // ⭐ All run concurrently
      scb.run();
    join_any
    #10; $finish;
  end
endmodule

Functional Coverage
covergroup · coverpoint · bins · illegal_bins · ignore_bins · cross · sample()
COVERAGE
Definition
Functional coverage measures which design scenarios were exercised during simulation. Unlike code coverage, it is user-defined and tied to the specification — you declare what matters, the tool tracks whether it occurred.
TermSyntaxPurpose
covergroupcovergroup cg; ... endgroupContainer for coverage points
coverpointcp_x: coverpoint var { bins ... }Track values of a variable
binsbins b1 = {v1, v2};Named value group
illegal_binsillegal_bins bad = {x};Error if this value is hit
ignore_binsignore_bins skip = {x};Exclude value from coverage %
crosscx: cross cp1, cp2;Track all combinations of two coverpoints
.sample()cg.sample();Manually trigger coverage sampling
get_coverage()cg.get_coverage()Returns coverage % as real
// ========================================================
// Topic 5: Functional Coverage
// File: 05_Functional_Coverage/functional_coverage_demo.sv
// ========================================================

class APBTransaction;
  rand bit [3:0]  addr;    // 0–15
  rand bit [1:0]  opcode;  // 00=READ 01=WRITE 10=IDLE 11=reserved
  rand bit        pready;

  // ⭐ COVERGROUP
  covergroup apb_cg;

    // ⭐ COVERPOINT with named bins
    cp_opcode: coverpoint opcode {
      bins read_op  = {2'b00};
      bins write_op = {2'b01};
      bins idle_op  = {2'b10};
      illegal_bins reserved = {2'b11}; // Error if hit
    }

    cp_addr: coverpoint addr {
      bins low_zone  = {[4'h0:4'h5]};
      bins mid_zone  = {[4'h6:4'hA]};
      bins high_zone = {[4'hB:4'hE]};
      ignore_bins reserved_top = {4'hF}; // Excluded
    }

    cp_pready: coverpoint pready {
      bins ready     = {1};
      bins not_ready = {0};
    }

    // ⭐ CROSS: all opcode × addr combinations
    cx_op_addr: cross cp_opcode, cp_addr;

  endgroup

  function new();
    apb_cg = new();   // ⭐ Must instantiate covergroup
  endfunction

  function void sample();
    apb_cg.sample();  // ⭐ Manually trigger
  endfunction
endclass

module functional_coverage_demo;
  APBTransaction t = new();
  initial begin
    repeat(50) begin
      if (!t.randomize()) $fatal(1,"Failed");
      t.sample();        // ⭐ Collect coverage each time
    end

    // Force corner cases
    t.randomize() with { opcode == 2'b01; addr == 4'hB; };
    t.sample();

    $display("Total coverage : %0.2f%%", t.apb_cg.get_coverage());
    $display("op coverage    : %0.2f%%", t.apb_cg.cp_opcode.get_coverage());
    $display("cross coverage : %0.2f%%", t.apb_cg.cx_op_addr.get_coverage());
  end
endmodule

Assertions (SVA) — Immediate & Concurrent
assert · property · ##n · |-> · |=> · $rose · $fell · disable iff · cover
SVA
Definition
SVA lets you write declarative rules that the simulator checks automatically every clock cycle. Immediate assertions check current values; concurrent assertions verify temporal (multi-cycle) behavior.
OperatorMeaningExample
##nExactly n clock cycles latera ##2 b → b true 2 cycles after a
##[m:n]Between m and n cyclesreq ##[1:5] ack
|->Overlapping implication (same cycle)a |-> b
|=>Non-overlapping implication (next cycle)a |=> b
$rose(s)Signal transitions 0→1$rose(psel)
$fell(s)Signal transitions 1→0$fell(ack)
$stable(s)Signal value unchanged$stable(paddr)
[*n]Repeat exactly n timesa[*3]
[*1:$]Repeat 1 or more timesa[*1:$]
disable iffSuppress during conditiondisable iff (rst)
// ========================================================
// Topic 6: Assertions (SVA)
// File: 06_Assertions_SVA/assertions_demo.sv
// ========================================================

module apb_checker (
  input logic clk, rst,
  input logic psel, penable, pwrite, pready,
  input logic [31:0] paddr, pwdata, prdata
);

  // ⭐ IMMEDIATE ASSERTION (procedural code)
  always @(posedge clk) begin
    if (psel && penable)
      assert (paddr[1:0] == 2'b00)
        else $error("[IMMED] PADDR not word-aligned!");
  end

  // ⭐ CONCURRENT ASSERTION — property + assert property

  // Rule 1: PENABLE must come 1 cycle after PSEL (|=> non-overlapping)
  property p_penable_after_psel;
    @(posedge clk) disable iff (rst)
    $rose(psel) |=> penable;   // ⭐ next cycle
  endproperty
  APB_PENABLE: assert property (p_penable_after_psel)
    else $error("PENABLE not seen 1 cycle after PSEL!");

  // Rule 2: Address must not change during transfer (|-> same cycle)
  property p_addr_stable;
    @(posedge clk) disable iff (rst)
    (psel && penable) |-> $stable(paddr);
  endproperty
  APB_ADDR: assert property (p_addr_stable)
    else $error("PADDR changed during transfer!");

  // Rule 3: PREADY must come within 1-5 cycles
  property p_pready_timeout;
    @(posedge clk) disable iff (rst)
    $rose(penable) |-> ##[1:5] pready;
  endproperty
  APB_PREADY: assert property (p_pready_timeout)
    else $error("PREADY timeout!");

  // ⭐ COVER: verify scenarios actually occur
  cover property (@(posedge clk) psel && penable && pwrite  && pready);
  cover property (@(posedge clk) psel && penable && !pwrite && pready);

endmodule

Expected Exam Questions

  1. Differentiate immediate and concurrent assertions.
  2. Write an SVA: "If req rises, ack must come within 3 cycles."
  3. Explain |-> vs |=> with timing.

⚠️ Common Mistake: Confusing |-> and |=>. |-> is overlapping — consequent checked same cycle. |=> is non-overlapping — consequent starts next cycle. APB uses |=> because PENABLE comes one cycle after PSEL.

Must Memorize

  • Immediate: assert(expr) else $error("...") — in always or initial
  • Concurrent: property p; @(posedge clk) ... endproperty + assert property(p)
  • |-> same cycle | |=> next cycle — most exam-tested distinction
  • ##n = n cycles later | ##[m:n] = between m and n cycles
  • disable iff (rst) = suppress assertion during reset
  • cover property = checks scenario occurs (not an error if missing)

APB Protocol (AMBA APB3)
IDLE · SETUP · ACCESS · PREADY wait states · apb_write · apb_read tasks
APB
Definition
The Advanced Peripheral Bus (APB) is a simple, low-bandwidth AMBA bus for slow peripherals (UART, GPIO, Timer). It is non-pipelined, uses a single master, and requires exactly 2 clock cycles minimum per transfer (SETUP + ACCESS).
SignalDirectionDescription
PCLK→ AllClock — all transfers sync to rising edge
PRESETn→ AllActive-low reset
PSELMaster→SlaveSelect: this slave is chosen
PENABLEMaster→SlaveEnable: marks 2nd cycle (ACCESS phase)
PWRITEMaster→Slave1=Write, 0=Read
PADDR[31:0]Master→SlaveAddress bus
PWDATA[31:0]Master→SlaveWrite data
PRDATA[31:0]Slave→MasterRead data
PREADYSlave→MasterReady: 0=insert wait state, 1=transfer done
PSLVERRSlave→MasterSlave error flag
State Machine & Timing
IDLE ──PSEL=1──▶ SETUP ──PENABLE=1──▶ ACCESS
                                            │ PREADY=0 → stay in ACCESS (wait state)
                                            └ PREADY=1 → back to IDLE

Timing (Write):
PCLK   : _⌐‾⌐_⌐‾⌐_⌐‾⌐_⌐‾⌐_
PSEL   : ____⌐‾‾‾‾‾‾‾‾‾‾‾⌐__
PENABLE: ________⌐‾‾‾‾‾‾‾⌐__
PWRITE : ____⌐‾‾‾‾‾‾‾‾‾‾‾⌐__ (1=Write)

module apb_protocol_demo;
  logic        PCLK=0, PRESETn=0;
  logic        PSEL=0, PENABLE=0, PWRITE=0, PREADY;
  logic [31:0] PADDR=0, PWDATA=0, PRDATA, rdata;

  always #5 PCLK = ~PCLK; // 100 MHz
  apb_slave slave (.*);

  // ⭐ APB WRITE TASK
  task apb_write(input logic [31:0] addr, data);
    $display("--- WRITE addr=%08h data=%08h ---", addr, data);

    // ⭐ SETUP phase: PSEL=1, PENABLE=0
    @(posedge PCLK);
    PSEL <= 1; PENABLE <= 0; PWRITE <= 1;
    PADDR <= addr; PWDATA <= data;
    $display("SETUP  : PSEL=1 PENABLE=0");

    // ⭐ ACCESS phase: PSEL=1, PENABLE=1
    @(posedge PCLK);
    PENABLE <= 1;
    $display("ACCESS : PSEL=1 PENABLE=1");

    // Wait for PREADY (handles wait states)
    do @(posedge PCLK); while (!PREADY);
    $display("DONE   : PREADY=1 → transfer complete");

    // Back to IDLE
    PSEL <= 0; PENABLE <= 0; PWRITE <= 0;
  endtask

  // ⭐ APB READ TASK
  task apb_read(input logic [31:0] addr,
                 output logic [31:0] rdata);
    $display("\n--- READ addr=%08h ---", addr);

    // SETUP phase
    @(posedge PCLK);
    PSEL <= 1; PENABLE <= 0; PWRITE <= 0; PADDR <= addr;

    // ACCESS phase
    @(posedge PCLK); PENABLE <= 1;

    // Wait for PREADY
    do @(posedge PCLK); while (!PREADY);
    rdata = PRDATA;
    $display("DONE   : PRDATA=0x%08h", rdata);
    PSEL <= 0; PENABLE <= 0;
  endtask

  initial begin
    repeat(2) @(posedge PCLK); PRESETn = 1;

    apb_write(32'h0000_0000, 32'hDEAD_BEEF);
    apb_write(32'h0000_0004, 32'hCAFE_BABE);
    apb_read (32'h0000_0000, rdata);
    apb_read (32'h0000_0004, rdata);

    $display("\nAPB Demo COMPLETE");
    $finish;
  end
endmodule

⚠️ Common Mistake: Asserting PENABLE=1 in the SETUP phase. PENABLE is 0 during SETUP and only becomes 1 in ACCESS. The transfer completes when PENABLE=1 AND PREADY=1.

Must Memorize

  • Minimum 2 cycles: SETUP (PSEL=1, PENABLE=0) → ACCESS (PSEL=1, PENABLE=1)
  • PREADY=0 → stay in ACCESS (insert wait states)
  • PREADY=1 → transfer complete → go back to IDLE
  • PWRITE=1 → Write (drive PWDATA) | PWRITE=0 → Read (capture PRDATA)
  • PSLVERR=1 → slave signalling an error condition
  • All APB signals are sampled at rising edge of PCLK
